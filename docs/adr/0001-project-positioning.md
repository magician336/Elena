# 0001 - 项目定位:Agent 原生嵌入式状态存储

2026-11-03,基于同日完成的需求、生态、产品形态与替代方案四方面调研的交叉定位,Elena 确立为 **Agent 原生嵌入式存储引擎(Bitcask 起步)+ agent 语义层(轨迹/会话/检查点)**,Go 实现,单二进制零外部依赖。选择依据:它是四方面证据——长期运行进程的状态负载在 Go 嵌入式生态中的空位、append-only 事件负载与 Bitcask 模型的结构契合、近邻产品能力组合的空缺、主张可全程由可复现测量支撑——唯一完全收敛的方向。

## Considered Options(否决理由均非显然,留档防复议)

- **eval 平台**:需求信号最强,但该功能域的差异化空间已被既有开源项目覆盖,独立重做的增量有限;评估能力由既有项目承接深化。
- **durable execution 独立项目**:AI 结合证据虽强,但工业窗口已关闭——Temporal(Go 编写,2.4 万 star、高频迭代,官方集成三大 Agent SDK)已定型,"为什么不用 Temporal"没有有说服力的回答。其事件溯源/检查点话题并入本项目语义层。
- **沙箱(E2B 兼容切片)**:外部需求信号强,但腾讯 CubeSandbox(7 个月 13.1k star)与 kubernetes-sigs/agent-sandbox 已占 Go 通用位,只剩切片缝隙;seccomp/namespace 的实现与运维复杂度超出本项目的边界。
- **代码检索引擎(zoekt 路线)**:需求信号单层、无交叉验证,且与存储引擎无结构复用。
- **向量检索引擎**:Go 生态位已满(milvus/weaviate),HNSW 的实现与调优成本高,且与 append-only 事件负载无结构关联。

## Consequences

- **质量流程**:测试先行(TDD)、覆盖率 ≥80%、双轴 code-review(标准轴 + 规格轴)作为每个阶段的验收防线;模块说明随代码同步维护。
- **文档分层**:决策记录(ADR)与术语表(GLOSSARY)随仓库发布;调研底稿与过程材料不随仓库分发,入库文档以决策结论与可复现证据为准。
- **工期**:MVP(引擎核心+语义层+证据)3 周硬顶(2026-11-03 → 11-24);LSM 升级为可选第 4 阶段(超时降级为"读源码讲权衡",不写码);Raft 组装只在 roadmap 留行。
- **对外文档措辞(项目级硬约束)**:所有对外文档以系统机制(WAL/合并/写放大/P99/故障恢复)为先,agent 只出现在场景描述行。
- **交付形态**:Go library + CLI 必做;MCP server 封装为可选 demo 层;不做 HTTP 服务;网页演示为单页静态(预生成数据,时间盒 2 天,降级为示例录屏)。
- 证据基线(benchmark 对比 bbolt/badger/rosedb、kill -9 故障注入、YCSB 风格读写比)与功能同优先级,进 CI。
